# Riichi Database — 天鳳牌譜データ分析パイプライン

> 天鳳（四人打ち）牌譜 → データパイプライン → 権威統計検証 → 読み筋分析
> パイプライン全面修復 + 検証ゲート体制 + nodocchi 統計ベースライン

---

## アーキテクチャ

```
天鳳 XML 牌譜 (354K 局の生データ)
      │  pipeline/tenhou_to_mjai.py   コンバータ（赤牌ID + 副露mビット権威デコード）
      ▼
MJAI イベントストリーム (games_200k_v2, 200K 半荘)
      │  pipeline/etl_v3.py           ETL（手牌トラッキング + 局級准入 ADR-005）
      ▼
v3_200k_v2.parquet (98.86M 行 / 2.05M 局)
      │  verify_gate.py               L0 アンカー → L1 ゴールデンセット → L2 不変量+回帰 → L3 統計ベースライン
      ▼
クエリ群 (analysis/queries + aka) → 結果 (results/)
```

## 主な成果

### 1. パイプライン修復（11 個の構造的バグ）

| Bug | 修復 | 検証 |
|-----|------|------|
| コンバータ m デコード誤り（副露タイプ錯乱）| 権威ビットレイアウトで書き直し | 手牌保存ゴールデンテスト |
| 赤5 ID 判定誤り（`cp==3` vs 権威 `id%4==0`）| 赤5 = 16/52/88 | 300 ファイルで 0 不一致 |
| 副露 consumed コピーID トラッキング誤り | カテゴリ単位の除去 | meld 失敗 31.8% → 0 |
| 国士/七対待ち漏れ、ドラ循環オフバイワン等 | 個別に修復 | INV-2 PASS |

### 2. データ純粋性原則（ADR-005）

- **局級准入**：1 局の全アクションが検証合格した場合のみ DB へ；コピー曖昧局（情報理論的 ~3.8%）は丸ごと破棄
- **現物 = 0 自己検証**：ある立直者に対する現物（立直者の全捨牌 + 立直後の他家捨牌）の放銃率は**正確に 0** でなければならない（振聴ルール）——非ゼロはロジックバグ。データ正当性の最強自己検証。

### 3. 検証ゲート（L0-L3）

- L0 アンカーテスト（8 ゴールデンケース）
- L1 ゴールデンセット（レアシナリオをカバーする 200 XML、AGARI 交差検証 ≥95%）
- L2 不変量（INV-1..10）+ 回帰プローブ（P1-P15）
- L3 統計ベースライン vs **nodocchi Phoenix DB**（270 プレイヤー / 2000 万局）

### 4. 統計ベースライン（`data/baseline_stats.json`）

| 指標 | 観測 | nodocchi ベースライン |
|------|------|---------------------|
| 和了率 | 21.1% | 21.9%（段位差）|
| 放銃率 | 12.5% | 13.1% |
| 立直率 | 18.7% | 18.2% |
| ツモ割合 | 40.9% | 40.4% |
| 赤ドラ割合 | 47.4% | 49.8% |
| 平和割合 | 20.3% | 20.5% |
| 七対子割合 | 2.9% | 2.9% |

### 5. 読み筋分析結果（`results/`）

- **現物/筋/無筋 安全度グラデーション**：現物 0% < 筋 3.1% < 無筋 8.1%（1対1の真実放銃率）
- **無筋内部分層**：中張 13.0% > 2·8 10.0% > 幺九 7.8% > 字牌 1.9%
- **赤5宣言**：赤5切りの後、同色端牌（1/9）待ちが増加、中張は減少；5x 待ち率 0%
- **押し引き**：聴牌時 立直者への放銃 4.0% vs 3向聴時 0.8%
- **副露クラス**：役牌流 +393 vs 断幺流 -125 点；染手オーバーフロー聴牌率は非オーバーフローの 3 倍
- 詳細：`results/RESULTS_README.md`

## 環境要件

- Python 3.13+（polars ≥1.40, psutil）
- Windows 固有の Python パスが `run_guarded.py`/`verify_gate.py` の `PY` 定数にハードコード（環境に合わせて変更）
- データ：天鳳公開牌譜 XML（354K 局、[tenhou.net](https://tenhou.net)）；本リポジトリは生データを含まない（大容量）
- ベースライン出典：nodocchi.moe Phoenix DB

## ディレクトリ構成

```
├── pipeline/          # データパイプライン（XML→mjai→parquet + 検証）
├── analysis/          # 分析スクリプト
│   ├── queries/       # クエリ群（B/V/H/L3/読み筋等）
│   ├── aka/           # 赤牌特化分析
│   ├── sanity/        # 統計ベースライン検証
│   └── gate/          # 検証ゲート（L0-L3 + メモリガード）
├── results/           # ★ 高価値統計結果（JSON）
├── data/              # ベースライン/ゴールデンセット（小ファイル）
└── docs/              # 主要ドキュメント
```

## 使い方

```powershell
# 統計ベースライン検証（nodocchi 連動ゲート）
python analysis/sanity/stats_sanity.py --data v3_200k_v2.parquet --mode warning

# 全検証ゲート（変更後は必ず実行）
python analysis/gate/run_guarded.py analysis/gate/verify_gate.py --all --data v3_200k_v2.parquet

# クエリ群の再実行（半荘級一様サンプリング）
python analysis/gate/run_guarded.py analysis/queries/b2_queries.py
```
