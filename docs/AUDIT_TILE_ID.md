## 二、关键发现

### 1. 副露 m 字段的真相（推翻 ADR-003 的 ID 推导）

天凤 XML 的 `<N m="..."/>` **不编码具体牌 ID（0-135）**，只编码：
- **类别**（数牌/字牌的 34 类之一）
- **被叫牌位置**（chi r / pon r）
- **赤显示标志**（副本位 0 → 电脳麻将显示为赤）

**权威 convlog.js 的 `mianzi()` 只做显示字符串**（`s + nn + d`），从不推导具体 ID。

### 2. 当前转换器 `_handle_n` 的错误

`tenhou_to_mjai.py _handle_n` 用 `t + ((m>>3)&3)` 等**推导具体 ID** 去 `_remove_tile_by_id` 移除手牌：

- chi：`h = [t + ((m>>3)&3), t+4+((m>>5)&3), t+8+((m>>7)&3)]`
- pon：`del h[unused]`（unused 来自 bit5-6）
- kan：`hai0 = (m & 0xFF00) >> 8; t = (hai0//4)*4; h = [t..t+3]`

**失败模式**（6,926 次）：
- pon 字牌 copy3（127/131/135 等）不在手牌——手牌里是其他副本
- chi 推导 copy 与手牌实际副本不符

**根因**：m 字段的"副本位"是**类别内相对编码**（电脳麻将显示用），**不等于牌山 ID 的副本号**（0-135 中 `id % 4`）。两者**独立**。

**影响**：当前转换器按 ID 移除导致 **31.8% 副露移除失败** → 后续手牌追踪连锁错误。**这是真 bug，需修复**（改按类别移除）。修复后 AGARI 一致率 96.19%（其余 3.81% 为信息论极限，见 §3b）。

### 3. 正确方案（Plan A 验证通过）

**按类别移除**：`_remove_tile_by_cat`（手牌中该类任意一张）→
- 移除成功率 **100%**（21,755/21,755）
- AGARI 手牌一致率 **96.19%**（4,322/4,493）

### 3b. AGARI 剩余 171 例失败归因（100% 同一根因）

**根因 = 副露 consumed 的副本选择歧义（信息论极限，非 bug）**：

天凤 `<N m="...">` 字段只编码**类别**（+被叫位置+赤显示标志），**不编码玩家用哪张副本（ID 0-135）吃/碰**。当手牌有多张同类别牌时（如 3p#1 + 3p#3），m 字段无法区分吃用哪张。

**机制**（代表性例 33104955 who=2）：
1. 手牌有 3p#1(45) + 3p#3(47)，吃 3p4p5p 用 45
2. 之后 `dahai 47`（打出 3p#3）
3. 重放按类别移除**第一张 47**（错）→ 打 47 失败 → 45 残留 → ev extra 3p#1

**归因统计**（171 失败 = 125 ron + 46 tsumo）：
- 79 例 same-cat-diff-copy（ev 多 X#a，ag 多 X#b 同类不同副本）
- 92 例 diff-cat 表现（同类副本歧义 + 连锁 dahai 失败残留）
- **192 个 ev extra 牌全部属于副露过的类别，0 例其他原因** → 100% 归因

**对数据的影响**：仅影响具体副本号（ID%4）准确性，**不影响**：
- 34 类别组成（hand_34）✅ 正确
- 张数守恒 ✅ 正确
- 摸切赤牌 ID（16/52/88）✅ 正确
- 所有基于类别的分析 ✅ 正确

### 4. 副露赤牌 ID 不可恢复

副露 m 字段的"副本位 0 = 赤"标志**与实际赤牌 ID（16/52/88）不对应**：
- 副本位 0 的 5x ID 分布均匀（16:269 / 52:276 / 88:285 vs 普通 5x 相当）
- "副本位 0 5x == 局内赤牌"仅 830 例 vs "≠" 6,898 例（83% 不符）

**含义**：副露消费的赤牌 ID **无法从 XML 确定**（除非 AGARI 揭示）。查询赤牌相关副露需注意此局限。

## 三、影响面

1. **手牌追踪**：所有副露行（chi/pon/kan）的 hand_34 在 ~32% 副露中移除错误 ID → 手牌组成错
   - 但**张数守恒**仍成立（移除数量对，ID 错）——这就是此前不变量/张数验证通过的原因
2. **AGARI 手牌**：96% 一致（按类别方案）→ 修复后可达 ~96-100%
3. **赤牌相关分析**：副露赤牌不可识别（新增局限）；摸切赤牌仍准确
4. **影响现有资产**：v3_10k/v3_200k.parquet 的手牌字段含此错误

## 三b. 数据纯净性原则（局级准入，2026-08-03 确立）

> **只有当一个小局（kyoku）的全部动作都验证合法时，该局才能进入数据库。任何局部不确定/违规 → 整局丢弃。** 数据纯净性优先于数据量。

### 原则内容

1. **局级验证，不是行级容错**：一个 kyoku 内任一行/动作触发以下任一情况 → **整局丢弃**（不进 parquet）：
   - 副露 consumed 移除失败（副本歧义残留，AGARI 交叉验证不一致）
   - dahai 移除失败（打出的牌不在手牌）
   - AGARI 手牌与事件流重放不一致（第 §3b 的 171 例）
   - 任何不变量违反（INV-1..10，见 GAME_MODEL.md §3）
2. **丢弃不静默**：ETL 记录丢弃原因与计数，可审计（`dropped_kyoku` 日志/计数）。
3. **保留原始 XML**：被丢弃的局仍保留在 `games/`（权威源），仅不进分析数据库；需要时可按局重放复核。
4. **基准**：AGARI 交叉验证一致率（修复后 96.19%）作为局级准入的硬门槛；剩余 3.81% 因信息论极限（副本歧义）被整局拒绝——**不降级入库**。

### 对构建的影响

- 修复转换器 `_handle_n` 按类别移除 + 按局标记"疑似歧义"→ ETL 构建时丢弃该局
- v3_10k/v3_200k.parquet 重建时应用此原则（含此前已入库的歧义局清理）
- 统计口径变化：**样本量以"纯净局"计**，所有分析基于纯净局子集
