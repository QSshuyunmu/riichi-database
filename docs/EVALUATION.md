### 根因回顾：转换器 m 解码错误（#8）

- **症状**：暗杠行 98% consumed 移除失败（hs=12）；"暗杠牌从未进手"之谜；副露行手牌系统性偏差
- **误判**：曾被定性为"mjai 格式固有局限——副露行手牌恒少 1"（51% 副露行），结论错误
- **真相**：`tenhou_to_mjai.py _handle_n` 把 **m 的低 2 位（来源座位）当作副露类型** → chi/pon 被误判为 kakan/ankan，consumed 牌全错（如吃 2p-3p-4p 变成"暗杠 7m×4"）
- **权威依据**：mjlog v4 位布局（tehai.js / libriichi / pymahjong / Akagi 四个独立实现一致）：bit2=吃、bit3=碰、bit4=加杠、无 flag=大明杠/暗杠（低 2 位=来源，0=暗杠）
- **验证**：01e8ec31 局 2 手牌守恒精确闭合（碰 F + 碰 9s + 吃 2m-3m-4m → AGARI 5 张）

### 根因回顾：赤牌 ID 判定错误（#10）

- **症状**：切赤 5m 宣言组手牌 5m≥1 占 **49.8%**，切普通 5m 组仅 30.8%——与牌理（切赤者必已切普通留赤，手牌普通 5x 应显著更少）**方向完全颠倒**
- **误判**：曾考虑"故意切 0x 引挂"（低概率）——无法解释 +19pp 系统性偏差
- **真相**：`tenhou_to_mjai.py id_to_pai` 用 **`cp == 3`**（ID 19/55/91）判赤；天凤赤牌实际 ID = **16/52/88**（`id % 4 == 0`，每类 5 号牌第 1 张副本）→ **赤/普通标签系统性互换**："切赤"组实为切普通 5 第 4 张（保留真赤，49.8% 符合牌理），"切普通"组混入切真赤行（30.8% 符合牌理）
- **权威依据**：kobalab/tenhou-log `lib/convlog.js` —— `if (type.hongpai && s != 'z' && n == 5 && pn % 4 == 0) n = 0;`
- **为何不变量未发现**：赤/普通同 34 类别位，所有守恒/计数验证不区分赤——**赤标记正确性只能靠权威源码对照 + 端到端 ID 级验证**
- **验证**：函数级 6 例 + 300 文件端到端（143,859 次摸牌、3,173 张赤牌 **0 失配**）

### 根因回顾：副露 consumed 副本 ID 追踪错误（#11）

- **症状**：AGARI 交叉验证失败率 42.9%（2015-08-03 审计，4,493 和牌中 1,926 不一致）；consumed 推导 ID 移除失败 31.8%（6,926/21,755）
- **真相**：天凤 `<N m="...">` **只编码类别**（+被叫位置+赤显示标志），**不编码具体副本 ID（0-135）**。`_handle_n` 用 `t + ((m>>3)&3)` 等推导 ID 是**猜测**，与手牌实际副本不符（如手牌有 3p#1 + 3p#3，吃用 #1 但推导移除 #3）
- **归因**：171/4493 例 AGARI 失败 **100%** 为副本歧义（信息论极限，m 字段无此信息）；192 个 ev_extra 牌全部属于副露过的类别
- **修复**：按类别移除 `_remove_tile_by_cat` + 输出实际被移除的牌（含赤标记与手牌一致）→ meld 失败 0
- **验证**：2000 文件 / 18,031 和牌 meld 移除失败 0；AGARI 一致率 95.58%（其余 3.8% 为信息论极限，纯净性原则整局丢弃）

## 四c. 数据纯净性原则（2026-08-03 确立，2026-08-04 已实现）

> **只有当一个小局（kyoku）的全部动作都验证合法时，该局才能进入数据库。任何局部不确定/违规 → 整局丢弃。** 数据纯净性优先于数据量。

**准入条件（G-1..G-4，详见 GAME_MODEL.md §4）**：
- G-1 副露 consumed 移除成功（无副本歧义残留）
- G-2 dahai 移除成功（打出的牌必在手牌）
- G-3 和牌局：AGARI 手牌与事件流重放完全一致（交叉验证，基准 96.19%）
- G-4 INV-1..10 全部满足

**执行**：局级丢弃（非行级）、丢弃不静默（记录原因/计数）、原始 XML 保留、**不降级入库**（副本歧义局直接拒绝）。**所有分析基于纯净局子集**。

**✅ 已实现（2026-08-04）**：
- 转换器 `_handle_n` 副露按类别移除（meld 失败 31.8% → 0）
- ETL `process_file` 局级准入：dahai/副露移除失败 → 整局丢弃 + `_DROP_STATS` 审计（实测 200 文件丢弃 0.73% 局）
- 丢弃后不变量 INV-2/INV-3 0 违反

## 四e. 查询口径系统性修复（2026-08-04，用户指正）

> 用户指正核心原则：**现物定义**（对一家立直的现物 = 立直家全部舍牌 + 宣言后他家舍牌）与**铳率必须一对一**（固定目标立直玩家）。据此审计发现并修复 3 类系统性问题：

### 1. 放铳/和率的"行级重复"（backfill 冗余到该家所有行）

`kyoku_result` 是整局结局，backfill 到该家每行（放铳家 ~11.3 行/局）→ 行级计数重复虚增。修复：**局级去重**（每 game,round,actor 唯一结局）。

| 查询 | 旧（行级）| 新（局级/一对一）|
|------|-----------|----------------|
| DQ1 现物/筋/无筋 | 现物 86.5%（假象）| **现物 0.000%**（规则强制）+ 无筋 8.11% > 筋 3.05% |
| DQ2 无筋分层 | 中张 60.6% 等（假象）| 中张 13.0% > 2·8 10.0% > 幺九 7.8% > 字牌 1.9% |
| DI1 押し引き | 向听0 放铳 12.3% | 向听0 放铳给立直家 **4.04%**，向听3 0.77%（5 倍差）|
| DI2 立直家数 | 放铳 9.77%/12.58% | 放铳给立直家 **1.46%/1.31%** |
| DI3 副露家追立 | 放铳 11.4% | 放铳给立直家 **2.81%** |
| TM1 第一副露巡目 | 行级 | 局级 13.4-13.7% |
| SK2 点差 | 行级 | 局级 14.7% |
| V4 副露大类和率 | 19-30%（虚高）| **3-5%**（局级真实）|

### 2. 时点判定用"turn 跨家比较"（副露后 turn 不递增）

`turn` 是每家自己的出牌次数，跨家不可比 → 改用**全局事件序号 `_seq`**（parquet 行顺序 = 事件顺序）。

### 3. 现物判定错误（"全局已见" ≠ 现物）

旧用 `kawa_visible[wt]>=1`（牌在任何人手里）当现物 → 应为一对一：**立直家全部舍牌 + 宣言后他家舍牌集**。修复后**现物放铳 = 精确 0**（振听规则强制，数据自检通过）。

### 4. 样本代表性：行截断 → 半庄级均匀抽样

`limit(5M)` 只覆盖 2021-01-01~17（前 5% 半庄）。修复：**半庄级均匀抽样**（按半庄起始行号取模）——覆盖全部 199,991 半庄 / 全年（2021-01 ~ 2022-01），局内事件完整。

### 5. 役种率 vs 权威基准验证（事件流 hora.yaku）

平和 20.26% vs 20.53% PASS / 七对 2.87% vs 2.93% PASS / 三色 3.73% vs 4.02% PASS / 断幺 22.06% vs 23.81% WARN（段位差）→ **yaku 消费正确**。

### 6. 内存护栏统一入口

所有长任务必须经 `run_guarded.py`（RSS>4GB 或系统可用<1.5GB → kill）；全脚本 step=30（~330 万行），峰值控制在 1.7-3.4GB。
