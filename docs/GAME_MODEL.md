# GAME_MODEL — 牌局运作模型（v3.5 全字段规范）

> 目的：把"对天凤/mjai 牌局运作模式的理解"显式化，作为代码实现的唯一依据。
> 原则：**定义 → 更新时机 → 不变量 → 示例** 四要素齐全；代码与本文档一一对应。
> 校验器（invariant_check.py / replay_truth.py）依据本文档的不变量与真值定义验证。
> 版本：v3.5（2026-08-04，纯净性原则落地实现 + 门禁/护栏体系后）

## 0. 牌局运作基础（事件流语义）

mjai 事件流（JSON Lines）是唯一权威源。12 类事件：

| 事件 | 语义 | 影响字段 |
|------|------|---------|
| start_game | 半庄开始（拼接文件可多个）| game_id 分块 |
| start_kyoku | 局开始（含 4 家初始手牌/局况/宝牌指示）| 全字段重置 |
| tsumo | 玩家摸牌（**chi/pon 后无 tsumo 事件**——规则：副露后不摸直接打）| 手牌/已见 |
| dahai | 玩家出牌（turn 在此递增）| 手牌/牌河/巡目 |
| chi/pon/daiminkan | 吃/碰/大明杠 | 副露/手牌 |
| ankan | 暗杠 | 副露/手牌 |
| kakan | 加杠（升级已有碰，**不新增副露**）| 副露 |
| reach / reach_accepted | 立直宣言/成立 | 立直状态/供托 |
| dora | 杠后宝牌追加 | 已见/宝牌指示 |
| hora | 和牌（双和 = 多次 hora，deltas 累加）| 结果/收支 |
| ryukyoku | 流局 | 结果/收支 |

**关键语义**：
- 巡目 turn 在 **dahai 时递增**（副露后的出牌也算新巡）
- **已见 = 已离开墙的牌**：初始 4 家手牌(52) + 每次摸牌 + 每次 dora 翻出。打出/副露是"位置移动"，**不增加已见**
- **杠后岭上摸（天凤 XML 特性）**：规则上所有杠（暗/加/大明）后必须摸岭上 1 张再打出，**但天凤 XML 不发出岭上摸的 T/U/V/W 事件**（转换器忠实转换 → mjai 无 tsumo）。ETL 以 `just_kan` 机制补回：杠后首次 dahai 时，**若打的牌不在手牌 → 该牌即岭上摸的牌（摸切）→ 补回再移除**（张数守恒）
- 立直供托：reach_accepted 扣 1000；hora deltas 含供托返还；ryukyoku 供托转下局（立直者仍 -1000）
- 多半庄拼接：start_game 块拆分 + `#N` 后缀 + 残局段（无 start_game 归属）丢弃

## 1. 字段规范

### 1.1 标识/上下文域

| 字段 | 定义 | 更新时机 | 不变量 |
|------|------|---------|--------|
| `game_id` | 半庄标识 = 文件名 + `#块号`（块 1 无后缀）| start_game 时块号递增 | 唯一；拼接文件同前缀多个 |
| `round_idx` | 局号（块内 0 起）| start_kyoku 递增 | 0..29；同一 (game_id, round_idx) 唯一局 |
| `turn` | 该玩家本局出牌次数（巡目）| **dahai 时 +1**（非 tsumo）| 1..20（极端长局可更多）；同 (game,round,actor) 递增唯一 |
| `actor` | 座位 0-3 | — | 0..3 |
| `tile` | 本次出牌（34 索引，赤牌归一化）| dahai | 0..33 或 -1 |
| `is_aka` | 本次出牌是否赤牌（5mr/5pr/5sr）| dahai | 0/1；is_aka=1 ⟺ 原牌 ∈ {5mr,5pr,5sr} |

### 1.2 切牌上下文域

| 字段 | 定义 | 更新时机 | 不变量 |
|------|------|---------|--------|
| `is_tsumogiri` | 是否摸切。宣言牌（reach 后第一打）字段恒 false → 用 `last_draw==tile` 推断；普通牌用原始字段 | dahai | 0/1；宣言牌行 = last_draw 推断 |
| `is_sengenhai` | 是否立直宣言牌（该行切牌即宣言）| dahai（reach 事件后）| 0/1；宣言行 = 该局 reach 后的第一个 dahai |
| `prev_tedashi` | 该玩家**上一次手切牌**（34 索引，无 = -1）| dahai 且非摸切 | -1..33；仅手切更新 |

### 1.3 手牌状态域

| 字段 | 定义 | 更新时机 | 不变量 |
|------|------|---------|--------|
| `hand_34` | 切牌后手牌 34 计数（**不含刚切的牌**）| dahai 移除后 | sum = 13 + 3×furo_count；每元素 0..4 |
| `shanten` | 向听数（mahjong 库，**普通形 + 七对 + 国士三取最小**，仅门清时计七对/国士）| dahai 后 | -1..8；99=异常 |
| `is_tenpai` | shanten ≤ 0 | 同上 | 0/1 |
| `waits_mask` | 听牌位 34-bit 掩码（mahjong 库逐张测试"加一张后向听<0"，普通形 + 七对 + 国士）| 同上 | is_tenpai=1 ⟹ waits≠0；popcount ≤ 34 |
| `wait_type_mask` | 听牌形 5-bit（1=两面 2=坎张 4=边张 8=单骑 16=双碰）| 同上 | 0..31；bit 由 `_classify_bit` 判定 |
| `dora_count` | 手牌+副露中宝牌数（赤牌 + 指示后继）| dahai 后 | 0..8+ |

**waits_mask 真值定义**：对每张牌 i（hand[i]<4），hand[i]+1 后向听 < 0 ⟹ bit i 置位。**必须与 mahjong 库一致**（shanten.py 贪心已弃用——历史上 16% 一致率）。**国士两种形态**：13 面（13 种幺九各 1）听全部 13 种；普通国士（11 单 + 1 双）只听缺的 1 种（试探 +1 后 kokushi 向听 < 0 判定，已验证不会把已有种误判为听）。**字牌单骑/双碰**：手牌 1 张听成对 = 单骑（wait_type 8）；手牌 2+ 张听成刻 = 双碰（16）。

### 1.4 副露域

| 字段 | 定义 | 更新时机 | 不变量 |
|------|------|---------|--------|
| `furo_count` | 副露数（chi/pon/daiminkan/ankan +1；kakan 不加）| 副露事件 | 0..4 |
| `furo_seq` | 副露序列 `[type,tile,type,tile,...]`；type: 0=chi 1=pon 2=daiminkan 3=ankan 4=kakan | 副露事件（kakan 更新既有 pon→4，不新增）| len = 2×furo_count；type 0..4；tile 0..33 |
| `furo_pon_honor` | 碰/大明杠字牌数（tile≥27）| pon/daiminkan | 0..4；≤ furo_count |
| `furo_yakuhai` | 碰役牌数（场风/自风/三元，连风去重）| pon/daiminkan | 0..4；≤ furo_pon_honor |
| `middle_suit_variety` | 副露后手切 3-7 中张的花色种类数（0-3）| dahai 且副露>0 且切 3-7 | 0..3；仅副露后累计 |

**役牌集合**（单一事实源）：{31,32,33} ∪ {27+bakaze} ∪ {27+seat_wind}（seat_wind=(actor-oya)%4）

### 1.5 牌河/已见域

| 字段 | 定义 | 更新时机 | 不变量 |
|------|------|---------|--------|
| `kawa_visible` | 全局已见张数（34 元素）= 初始 4 家手牌 + 摸牌 + dora 翻出；**不含"打出"（位置移动）**；含本行切牌（其已在初始/摸牌计过）| start_kyoku 初始化(52+dora)；tsumo +1；dora 事件 +1 | 每元素 **0..4**；sum = 52 + 1(首指示) + 局内 tsumo 数 + dora 事件数 |

**"已见"定义**：该牌已离开墙（可见于任何区域：手牌/牌河/副露/宝牌指示）的张数。打出/副露不改变已见（牌仍在"已见"集合内，只是换了位置）。**历史上 dahai +1 的重复计数 bug 即违反此定义**（导致已见>4）。

### 1.6 局况域

| 字段 | 定义 | 更新时机 | 不变量 |
|------|------|---------|--------|
| `kyoku_scores` | 局起始 4 家点数 | start_kyoku | 4 元素；sum ≈ 100000 + 供托 |
| `actor_score` | 本行玩家局起始点数 | start_kyoku | = kyoku_scores[actor] |
| `is_oya` | 本行玩家是否亲家 | start_kyoku | 0/1 |
| `seat_wind` | 本行玩家自风（(actor-oya)%4）| start_kyoku | 0..3 |
| `kyoku_num` | 局数 1-4（东/南场）| start_kyoku | 1..4 |
| `honba` | 本场数 | start_kyoku | 0.. |
| `kyotaku` | 供托数（继承棒，局初始）| start_kyoku | 0..；和牌局后 = 0（被和牌者取走）；流局局后 = 继承 + 本局立直数（留场）|
| `bakaze` | 场风 0=E 1=S | start_kyoku | 0/1 |

### 1.7 结果域

| 字段 | 定义 | 更新时机 | 不变量 |
|------|------|---------|--------|
| `kyoku_result` | 本局结局：0=win 1=tsumo 2=deal_in 3=tsumo_loss 4=draw 5=pass（-1=未知）| backfill（hora/ryukyoku 后）| -1..5；和牌局 4 家各有值 |
| `kyoku_pt_delta` | 本局收支 = deltas - 1000×本局立直（供托）；ryukyoku deltas 已含结算 | backfill | 与链式分数一致 |
| `win_tile` | **本局和牌牌**（全局共享，双和取第一张）：自摸=和牌者最后摸牌；荣和=放铳者最后打出牌 | backfill | -1..33；和牌局(kyoku_result∈{0,1} 存在)必有值 |
| `ryukyoku_type` | **流局类型**：-1 非流局；0 荒牌 1 流局满贯(nm) 2 九种九牌(yao9) 3 四风连打(kaze4) 4 四家立直(reach4) 5 三家和(ron3) 6 四杠散(kan4) | backfill（RYUUKYOKU type）| -1..6 |

**链式真值**（最强校验）：局 i 的 kyoku_scores + kyoku_pt_delta = 局 i+1 的 kyoku_scores（全链一致）。

**流局语义**（天凤权威，2026-08-03 联网确认）：

| 类型 | 成立条件 | 结算 | 连庄 |
|------|---------|------|------|
| 荒牌流局（type 无）| 牌墙摸完剩 14 王牌 | **听牌罚符**（不听者合计 3000+本场按人数均分；1 不听 -3000/2 不听各 -1500/3 不听各 -1000；听牌者均分收入）| 亲家听牌连庄，不听流庄 |
| 流局满贯（nm）| 配牌 10+ 种幺九且牌河无鸣牌 | **比照自摸满贯结算**（+8000 等，非罚符）| 亲家听牌连庄 |
| 九种九牌（yao9）| 第一巡 9+ 种幺九、无鸣牌（可选择）| 无结算 | **无条件连庄** +1 |
| 四风连打（kaze4）| 第一巡四家同打一种风牌、无鸣牌 | 无结算 | 无条件连庄 +1 |
| 四家立直（reach4）| 四家立直成立（最后立直者放铳不成立）| 无结算（供托留场）| 无条件连庄 +1 |
| 三家和（ron3）| 一家打牌同时放铳三家 | **不结算** | 无条件连庄 +1 |
| 四杠散（kan4）| 4 杠（≥2 家），第四杠者打牌无放铳/岭上自摸/抢杠 | 无结算 | 无条件连庄 +1 |

### 2a. 转换器 m 编码规范（tenhou_to_mjai.py `_handle_n` 权威解码）

天凤 XML `<N who="w" m="M"/>` 的 M 位布局（mjlog v4，tehai.js/libriichi/pymahjong/Akagi 一致）：

| 位 | 含义 |
|----|------|
| bit0-1 | **来源座位**（相对，0 = 暗杠；绝对 = (who + rel) % 4）——**不是副露类型**（历史误判根因）|
| bit2 (0x4) | 吃（chi）|
| bit3 (0x8) | 碰（pon）|
| bit4 (0x10) | 加杠（kakan）|
| bit5-6 | 碰/加杠的"未使用/新增副本号"（**不是拔北**）|
| 无 bit2-4 | 大明杠（bit0-1 ≠ 0）或暗杠（bit0-1 = 0）|
| 低 6 位 == 0x20 | 拔北（nukidora，仅三麻；**必须整 0x20 判定**，不能只查 bit5）|

牌解码：
- 吃：`t = (M & 0xFC00) >> 10`；`r = t % 3`；`t = t//3`；`t = 9*(t//7) + t%7`（7 宽块展开 9 宽）；`t *= 4`；三张 = `[t + ((M>>3)&3), t+4+((M>>5)&3), t+8+((M>>7)&3)]`，r 交换后 h[0] = 被叫牌
- 碰/加杠：`t = (M & 0xFE00) >> 9`；`r = t%3`；`t = (t//3)*4`；碰：副本 4 选 3（去掉 `((M&0x60)>>5)` 号）；加杠：`added = (M&0x60)>>5` 为新增第 4 张
- 杠：`hai0 = (M & 0xFF00) >> 8`；`t = (hai0//4)*4`；`r = hai0 % 4`；4 张副本 = `[t..t+3]`

**手牌守恒验证**（golden test）：01e8ec31 局 2——碰 F + 碰 9s + 吃 2m-3m-4m，AGARI 手牌 5 张（4m,5m,6m,S,S）精确闭合；旧解码把吃 2p-3p-4p 误判为"暗杠 7m×4"（consumed 牌从未进手）。

## 2c. 赤牌 ID 编码规范（tenhou_to_mjai.py `id_to_pai` 权威赤判定）

天凤 tile ID（0-135）：每 4 个 ID 为同种牌的第 1-4 张副本（`category = id // 4`，`copy = id % 4`）。

**赤牌 = 5 号牌的第 1 张副本**（`id % 4 == 0`），即：

| 花色 | 类别 | 赤牌 ID | 普通 5 其他 ID |
|------|------|---------|---------------|
| 万（5m）| 4 | **16** | 17, 18, 19 |
| 筒（5p）| 13 | **52** | 53, 54, 55 |
| 索（5s）| 22 | **88** | 89, 90, 91 |

权威依据：kobalab/tenhou-log `lib/convlog.js`：

```js
if (type.hongpai && s != 'z' && n == 5 && pn % 4 == 0) n = 0;  // 赤牌 = pn % 4 == 0
```

**历史错误**：`cp == 3`（ID 19/55/91 判赤）——那是普通 5 的第 4 张。后果：赤/普通标签系统性互换（详见 ADR-004）。

**语义后果**（为什么此前验证未发现）：赤/普通在 34 类别上同一位 → 手牌守恒、已见计数等全部不变量不受影响；只有显式消费赤标记的分析（is_aka、赤宝计数）受影响。**因此赤牌 ID 正确性必须对照权威源码验证，不变量无法覆盖。**

## 4. 数据纯净性原则（局级准入，2026-08-03 确立）

> **只有当一个小局（kyoku）的全部动作都验证合法时，该局才能进入数据库。任何局部不确定/违规 → 整局丢弃。** 数据纯净性优先于数据量。

### 4.1 准入条件（全部满足才入库）

| # | 条件 | 验证 |
|---|------|------|
| G-1 | 全部副露 consumed 移除成功（无副本歧义残留）| 事件流重放：移除失败即违规 |
| G-2 | 全部 dahai 移除成功（打出的牌必在手牌）| 事件流重放 |
| G-3 | 和牌局：AGARI 手牌与事件流重放完全一致 | AGARI（天凤服务器权威）交叉验证 |
| G-4 | INV-1..10 全部满足（含流局局）| invariant_check |

### 4.2 执行规则

- **局级，非行级**：任一行违规 → 整局丢弃（不进 parquet）
- **丢弃不静默**：ETL 记录丢弃原因与计数（`dropped_kyoku` 日志），可审计
- **原始 XML 保留**：被丢弃局仍留在 `games/`（权威源），需时可按局重放复核
- **不降级入库**：信息论极限（副露 consumed 副本歧义，§2b-4）导致的 AGARI 不一致局**直接拒绝**，不以"部分正确"入库

### 4.3 与历史局限的关系

- 已知格式局限（§2b-1 杠后手切岭上未知 / §2b-4 副露副本歧义）**不再静默容忍**——触发的局整局丢弃
- 语义权衡：样本量 = 纯净局子集；**所有分析基于纯净局**，保证结论可复现、可追溯

### 4.4 实现状态（2026-08-04 已落地）

- **转换器** `_handle_n`：副露按类别移除（`_remove_tile_by_cat`），m 字段只编码类别不编码副本 ID；输出用实际被移除的牌（含赤标记，与手牌一致）→ meld 移除失败 0（修复前 31.8%）
- **ETL** `process_file`：dahai/chi/pon/daiminkan/ankan/kakan 移除失败 → 标记违规局 `(game_idx, round_idx)` → 局尾整局过滤 + `_DROP_STATS` 丢弃审计（worker 汇总，run 打印）
- **实测**：200 文件 ~10,000 局丢弃 73 局（0.73%）；丢弃后 INV-2/INV-3 0 违反
- **验证链路**：verify_gate.py L0-L3 门禁（全过才全量）+ mem_guard.py 内存护栏（防 OOM）

## 5. 已知数据格式局限（无法从数据修复，查询须注意）

1. **杠后手切（摸岭上保留、打旧牌）**：ETL `just_kan` 仅覆盖"杠后摸切岭上"（打的牌 = 岭上牌）；若玩家保留岭上打旧牌，**岭上牌内容未知**（张数层面：验证显示 10K 暗杠行 100% hs=10 守恒，摸切路径；手切路径内容不可恢复）→ **按纯净性原则（G-1..G-3）整局丢弃或标记**
2. **源数据异常文件**：个别局出现牌张数违反物理（如同牌 6 张）→ 违反 INV-3 → 整局丢弃
3. **kakan 无碰上下文**：个别文件加杠无先前碰（源异常）→ 违反 G-1 → 整局丢弃
4. **副露 consumed 副本歧义（2026-08-03 审计发现）**：天凤 `<N m>` 只编码类别，不编码具体副本 ID（0-135）；手牌多张同类别时无法确定吃/碰用哪张 → AGARI 交叉验证不一致（3.81%）→ **整局丢弃（G-3）**
5. **副露赤牌 ID 不可恢复（2026-08-03 审计发现）**：m 字段"副本位 0=赤"标志与实际赤牌 ID（16/52/88）83% 不符 → 副露赤牌无法从 XML 确定 → 查询赤牌副露需注意（摸切赤牌仍准确）
